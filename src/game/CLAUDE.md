# src/game/ — the playable layer

Parent: [`../CLAUDE.md`](../CLAUDE.md) → [`/CLAUDE.md`](../../CLAUDE.md).
Read the root file first for the model policy and the mandatory update
rule (any change here updates this file **and** the root repo map).

## Why this folder exists

`/chapters` already presented the resume as prose in boxes, and `/plain`
presented the same facts better. The game surface had no reason to
exist: the panels were the same words, the "dialogue choices" only
scrolled to a panel you could have scrolled to yourself, and the panel
widths alternated down the page so the text visibly zig-zagged. The
reported symptom was "the text is all over the place… lack of fluency."

The fix was not decoration. **An episode needed a verb.** This folder is
that verb: a walkable floor with five doors, and one small game behind
each, where the facts surface *because you played*, not as a wall of copy
you scroll past.

## The three ideas that hold it together

**1. The floor is inside the window.** The title screen is a city at
night with one window lit. `/floor` is the inside of that window: a desk
with the lamp still on, then a corridor whose windows look out on the
same skyline, parallaxing as you walk. This is the whole reason the
overworld is drawn on a canvas rather than assembled from DOM — it has to
read as *somewhere inside the place you were already standing*. The theme
jump between the menu and the chapter screen was a real reported defect
once already (root `CLAUDE.md` phase 4). This is the same trap, and this
is the countermeasure.

**2. Locked doors are only legal because the stairs exist.** Door N is
dark until episode N−1 is cleared. That is a real lock, and spec §2 rule
1 forbids gating content behind interaction. It is allowed here **only**
because the floor is not the only way in: the stairwell in the corridor
goes to `/chapters` (the ungated Episode Explorer, every episode readable
in any order), `/plain` is one click from anywhere, and a locked door
says so and points at the stairs. `Play.jsx`'s results card additionally
offers the next door after two failed runs. **If you ever remove the
stairwell, or make the Explorer depend on progress, you have broken the
spec.**

**3. The mechanic is a metaphor for the work, never a trophy ceremony.**
"Collect the skill coins" is the failure mode this concept exists to
avoid. You stack semesters into a tower that becomes a building in the
skyline; you triage a hall with more raised hands than one person can
reach; you watch four meters drain because you cannot save all four; you
fly a night that took six tries to finish; you write a short program, run
it, and watch it break on one instruction so you can fix that instruction. The corniness trap in a resume game is the
resume-owner being the hero — here the visitor is the one with agency and
the games are allowed to be *hard and honest*.

`FORTY-EIGHT HOURS` **used to be** deliberately unwinnable past second
place, because the record it carried was three second places and a
national top ten, and a game that handed you gold he had not taken would
have been a nicer game and a dishonest one.

**That changed this batch, and it changed because the record changed,
not because the ending was softened.** The national final of atomcamp's
National AI Hackathon '26 was won outright. An ending frozen short of
first place now *understates* the record rather than protecting it, so
the finale keeps scrolling the last `FIRST_PLACE_LEAD` hours after the
clock stops: the player passes over the second-place roof, climbs, and
lands on the lit tower.

**The rule that did not change, and the one actually worth guarding:
the ending states exactly the result that happened, no more.** It was
never "the player must lose." If the record is ever re-cut shorter, cut
the ending back with it rather than leaving a win on screen that nobody
earned.

## Rules for whoever touches this folder

- **No colour literals, no font stacks.** Colour comes from `ctx.palette`,
  faces from `draw.js`'s `DISPLAY`/`BODY`.
- **No copy in a scene file.** `../data/games.js` owns every word a
  player reads; a scene owns the mechanic. A game surface that invents a
  credential is the one failure this project cannot absorb.
- **Reveals must be a complete prefix of `beats[]`** — start at 0, step by
  1, never skip. That is what guarantees a player reads the episode in
  order with no holes, however far they got.
- **There is no `'lose'` outcome.** A run that ends early still lands on
  the results card with everything uncovered, and still offers the way
  onward. The game may be lost; the resume may not be locked.
- **Run `npm run verify:scenes`** after any scene change. It drives every
  scene's real `update()`/`draw()` against a stub 2D context under three
  input modes (pointer only, keyboard only, hold) and checks the contract
  above, listener cleanup, and that nothing throws. It exists because the
  Browser pane in this environment does not run `requestAnimationFrame`
  (measured: 0 ticks in 500ms), so the games cannot be played in it —
  static rendering can be screenshotted, behaviour cannot.
- Performance: no `shadowBlur`, no per-object gradient allocation in a
  frame loop, precompute static geometry in `init()`.
- **Punctuation pass (this batch):** `scenes/overworld.js`'s two
  reader-facing strings — the stairwell `hint` and the door caption
  joiner (`▲ / E   ${line}`, previously `▲ / E  —  ${line}`) — had their
  em dashes removed on user instruction. No geometry or event logic
  changed; `npm run verify:scenes` still passes.
