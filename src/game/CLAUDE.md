# src/game/ — the playable layer

Parent: [`../CLAUDE.md`](../CLAUDE.md) → [`/CLAUDE.md`](../../CLAUDE.md).
Read the root file first for the model policy and the mandatory update
rule (any change here updates this file **and** the root repo map).

## Why this folder exists

`/chapters` already presented the resume as prose in boxes, and `/plain`
presented the same facts better. The game surface had no reason to
exist: the panels were the same words, the "dialogue choices" only
scrolled to a panel you could have scrolled to yourself, and the panel
widths alternated down the page so the text visibly zig-zagged. The
reported symptom was "the text is all over the place… lack of fluency."

The fix was not decoration. **An episode needed a verb.** This folder is
that verb: a walkable floor with five doors, and one small game behind
each, where the facts surface *because you played*, not as a wall of copy
you scroll past.

## The three ideas that hold it together

**1. The floor is inside the window.** The title screen is a city at
night with one window lit. `/floor` is the inside of that window: a desk
with the lamp still on, then a corridor whose windows look out on the
same skyline, parallaxing as you walk. This is the whole reason the
overworld is drawn on a canvas rather than assembled from DOM — it has to
read as *somewhere inside the place you were already standing*. The theme
jump between the menu and the chapter screen was a real reported defect
once already (root `CLAUDE.md` phase 4). This is the same trap, and this
is the countermeasure.

**2. Locked doors are only legal because the stairs exist.** Door N is
dark until episode N−1 is cleared. That is a real lock, and spec §2 rule
1 forbids gating content behind interaction. It is allowed here **only**
because the floor is not the only way in: the stairwell in the corridor
goes to `/chapters` (the ungated Episode Explorer, every episode readable
in any order), `/plain` is one click from anywhere, and a locked door
says so and points at the stairs. `Play.jsx`'s results card additionally
offers the next door after two failed runs. **If you ever remove the
stairwell, or make the Explorer depend on progress, you have broken the
spec.**

**3. The mechanic is a metaphor for the work, never a trophy ceremony.**
"Collect the skill coins" is the failure mode this concept exists to
avoid. You stack semesters into a tower that becomes a building in the
skyline; you triage a hall with more raised hands than one person can
reach; you watch four meters drain because you cannot save all four; you
fly a night you cannot win; you wire five modules onto one shared graph
and watch a change propagate. The corniness trap in a resume game is the
resume-owner being the hero — here the visitor is the one with agency and
the games are allowed to be *hard and honest*.

`FORTY-EIGHT HOURS` is deliberately unwinnable past second place. The
real record is three second places and a national top ten; a game that
let you take gold would be a nicer game and a dishonest one. **Do not
"fix" it.**

| `engine.js` | ✅ | The loop, shared by the overworld and all five games. Fixed 960×540 virtual box, letterboxed into whatever space it is given, so level geometry is identical on a 375px phone and a 2560px monitor and no scene does its own scaling maths. Letterbox bars paint `--ink`, which is every scene's ground colour, so on a tall phone they read as frame rather than as a broken layout. `update()` runs a fixed 60Hz accumulator (a variable dt would make jump heights depend on the visitor's refresh rate), clamped to 5 steps so a backgrounded tab returning after 30s replays a third of a second rather than 1,800 physics steps in one blocking frame. Input is **named actions**, never raw keys, so a scene says `pressed('action')` and the Space/Enter/Z/tap mapping lives in exactly one place; a `blur` handler releases everything, because a tab switch mid-hold never delivers the keyup and would otherwise leave a runner holding 'action' forever. `onKeyDown` returns early when the event target is inside a real `button`/`a`/`input`, so canvas keys never swallow activation of the page's own chrome. **This interface is frozen** — five scenes are written against it; add to the scene context rather than changing what is there. |
| `draw.js` | ✅ | The shared ink vocabulary, and the reason five separately-built minigames look like one game. Mirrors the language already set by `../components/EpisodeArt.jsx` and `../components/TitleBackdrop.jsx`: flat silhouettes, rim light toward the source, roughened contours, halftone falloff instead of smooth gradients. Key primitives: `litWindow()` draws every light twice (halo + core) because a flat pale rect reads as a grey square, not as a light that is on — the exact defect that forced `TitleBackdrop.jsx`'s round-3 rebuild, so **do not simplify it to one `fillRect`**; `withRim()` draws a silhouette twice, offset toward the light, because a 100%-ink shape in front of a glow reads as a hole punched in the frame rather than a person; `figure()` is deliberately asymmetric with a real neck, sloping shoulders and hanging arms, since a symmetric no-neck capsule reads as a snowman (a named defect in `EpisodeArt.jsx`'s rebuild); `roughRect()` keeps jitter to 2–6px, matching `Panel.jsx` — deeper jitter reads as a flame outline, which was a real `MemoryToast.jsx` defect. `grain()` composites **`soft-light`, not `overlay`**: overlay against an `--ink` ground pushes mid-grey noise toward brown and visibly muddied the whole frame. `rng()` is seeded — scene geometry must look the same every reload; only transient screen shake uses `Math.random()`. |

| `scenes/handsUp.js` | ✅ | Episode 2, TEACHING & RESEARCH — triage. A raked hall of 63 seated silhouettes, front-lit from the lectern; a raised hand is the one thing drawn in bone, ending in a `litWindow` pane that **dims as its time runs out**, so the timer is a light going out rather than a bar. Difficulty ramps on `max(time/14s, answered/5)` — driven by **answers, not time alone**, because a time-only ramp let a quick player finish in under 9 seconds with zero give-ups and the outro line unearned. Tuned by headless simulation across five bot cadences. **This batch — the two inputs were not the same game, reported live as "EXTREMELY EASY when I use KeyBoard and extremely hard when I use mouse."** Both halves were real. **Keyboard was a free win:** `ensureSelection()` re-targeted the MOST URGENT raised hand whenever the selection went stale, so after every answer the cursor was handed the objectively-optimal triage target at no cost and the run could be won by mashing Space twelve times without ever pressing an arrow — the arrows were decorative. It now falls back to the raised hand **nearest in screen space to wherever the cursor last sat** (tracked by a new `selectSeat()` helper). | `scenes/eventDay.js` | ✅ | Episode 3, LEADERSHIP & COMMUNITY — management. Four meters draining on coprime sine rhythms (17/23/13/29s) so the worst one changes hands ~14 times a day and a fixed rotation stops working. Collapse is counted and cripples that meter for the rest of the run but **never ends it early**. Tuned by simulating the day against six play policies; a good player finishes low but alive and nobody can hold all four full, which is what earns the outro. Attaches its own `window` keydown listener for digits 1–4 (the engine's KEY_MAP has no digits) and releases it in `dispose()`. **This batch — a collapse is now FINAL**, on the live report that "you can for some reason go up in a part even if that one part has reached 0." The old model marked a zeroed meter `collapsed` (permanent 1.5× drain) but left it refillable above `REARM_AT`, so a thing that had visibly died climbed back off the floor — which reads as the game not meaning what it just showed you. A meter that reaches 0 is now `dead`: it stays at 0, drains nothing further, and can never be selected or worked again. `nextAlive()` / `selectExact()` / `selectDirection()` replace the old `select()`, so the arrows, the 1–4 digit handler and the pointer hit test all skip a dead column outright, and selection auto-advances if the meter you are holding dies under you. `COLLAPSE_DRAIN` and `REARM_AT` were removed rather than left as dead constants. **The one thing that had to be got right:** if every meter dies the run ends, but it flushes every not-yet-revealed beat in order first — beats are paid out on a time schedule here and are the reason the screen exists, so an early wipe may cost the door and may never cost the content. `drawColumn()` marks a dead meter with a blacked-out shaft and a single corner-to-corner strike within the existing palette; no icon, `--signal` budget unchanged. **The header's simulated policy table was re-run and rewritten** for the new model: good play still keeps all four alive (0 lost at both the 'sharp' and 'good' policies), and no policy loses a meter before 34s — so `START_VALUE`, `REFILL` and the `METER_SPECS` bases were deliberately left alone. ## Rules for whoever touches this folder

- **No colour literals, no font stacks.** Colour comes from `ctx.palette`,
  faces from `draw.js`'s `DISPLAY`/`BODY`.
- **No copy in a scene file.** `../data/games.js` owns every word a
  player reads; a scene owns the mechanic. A game surface that invents a
  credential is the one failure this project cannot absorb.
- **Reveals must be a complete prefix of `beats[]`** — start at 0, step by
  1, never skip. That is what guarantees a player reads the episode in
  order with no holes, however far they got.
- **There is no `'lose'` outcome.** A run that ends early still lands on
  the results card with everything uncovered, and still offers the way
  onward. The game may be lost; the resume may not be locked.
- **Run `npm run verify:scenes`** after any scene change. It drives every
  scene's real `update()`/`draw()` against a stub 2D context under three
  input modes (pointer only, keyboard only, hold) and checks the contract
  above, listener cleanup, and that nothing throws. It exists because the
  Browser pane in this environment does not run `requestAnimationFrame`
  (measured: 0 ticks in 500ms), so the games cannot be played in it —
  static rendering can be screenshotted, behaviour cannot.
- Performance: no `shadowBlur`, no per-object gradient allocation in a
  frame loop, precompute static geometry in `init()`.
