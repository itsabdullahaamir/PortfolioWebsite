| `App.jsx` | ✅ | The router root. `<BrowserRouter>` wrapping `ProgressProvider` → `SettingsProvider` → `MusicProvider` → `ToastProvider` → `<Routes>` for `/` (`TitleScreen`), `/chapters` (`ChapterSelect`), `/chapters/:id` (`EpisodeView`), `/plain` (`PlainResume`), per spec §7 "Routing". The old default-`create-vite` template markup and its dead imports (`./assets/react.svg`, `./assets/vite.svg`, `./assets/hero.png`, `./App.css`, the `/icons.svg` sprite) were deleted, not recreated — none of those files exist and none are part of the spec. **Fixed post-deploy:** `BrowserRouter` now takes `basename={import.meta.env.BASE_URL}`. Without it, the live GitHub Pages site (served from `/PortfolioWebsite/`, see root `CLAUDE.md` §9) rendered a blank page — React Router matched routes against the full pathname including the subpath, so `/PortfolioWebsite/` matched nothing and every screen 404'd silently (console: `No routes matched location`). `BASE_URL` is `/` in dev, so local behavior is unchanged. The four routes are nested under one path-less layout route, `<Route element={<AnimatedOutlet />}>`, instead of each having a top-level `element` — `AnimatedOutlet` (defined in this file) uses `useOutlet()` + `AnimatePresence mode="wait"` to drive a route-change transition (`../components/PageTransition.jsx`, a curtain-wipe/parallax effect — not spec-mandated, added on direct user request). This restructuring exists specifically because the more commonly documented `<Routes location={location} key={location.pathname}>` pattern failed in manual testing (new screens never mounted after a navigation) in this project's react-router-dom 7 + framer-motion 13 combination; `useOutlet()` is the standard fallback. See root `CLAUDE.md` Phase 6 for the full verification notes, including a caveat that the animated path itself couldn't be screenshotted in the sandboxed test environment used this batch. **This batch — `AnimatedOutlet` gained two responsibilities**, both driven by `PageTransition.jsx`'s rebuild from a curtain wipe into a directional camera dolly (see that file's row in `components/CLAUDE.md`). (1) It calls `noteRouteChange(location.pathname)` **during render**, not in an effect: the transition now has a direction (in when going deeper, out when returning to the menu), and the outgoing screen is an element `AnimatePresence` is holding onto — its props are frozen at the previous navigation's values, so it cannot be told the answer by prop, only by a module-level value set before either child renders. It is idempotent per pathname, so StrictMode's double render is harmless. (2) A `useLayoutEffect` resets `window.scrollTo(0, 0)` on every pathname change — standard SPA behaviour this app never had (React Router does not reset scroll), and now load-bearing, because the transition wrapper is viewport-`fixed` while animating: without it a long screen would snap from the top the animation framed it at to a stale scroll offset the instant it settled. `PageTransition.jsx` freezes the OUTGOING screen's own scroll offset (captured inside `noteRouteChange`, before this effect runs) so the reset doesn't yank it mid-fade. **This batch — `MusicProvider` added, and `<AmbientLayer />`/`<BackgroundMusic />` are now mounted here as direct siblings of `<Routes>`, outside `<AnimatedOutlet />`:** `BackgroundMusic.jsx` (the main-menu "radio") used to be mounted by `MainMenu.jsx`, so it stopped on every navigation away from the menu, including into `/plain`. Direct user follow-up: it should keep playing across menu-ish navigation and only stop specifically on entering `/chapters` or `/chapters/:id`. Mounting it here means it never unmounts on route change; it gates its own play/pause on `useLocation()` internally and on `MusicProvider`'s `started` flag (new `context/MusicContext.jsx`), which `TitleScreen.jsx` flips true the moment its beat sequence reaches MENU — so it still never starts during beats 0–2. Verified live: paused entering `/chapters`/`/chapters/:id` with `currentTime` preserved, resumed (not restarted) on returning to `/` or `/plain`. **This batch — that route gate is gone and the description above is superseded.** Direct user request that the chapter-select and episode screens keep the music playing "alike it is in the Plain Resume Setting." `BackgroundMusic.jsx` no longer reads `useLocation()` at all; it plays whenever the `music` setting is on and `MusicProvider`'s `started` flag is set. Nothing in THIS file changed — mounting `<BackgroundMusic />` here as a sibling of `<Routes>` is what already made this possible — but the row is corrected so it doesn't describe a pause that no longer happens. The practical difference: the `<audio>` element is now untouched by navigation, so a track continues across a route change rather than pausing and resuming at the same offset. See `components/CLAUDE.md`'s `BackgroundMusic.jsx` row for the live verification numbers. **This batch — `<EscapeBack />` added as another headless sibling of `<Routes>`, inside `<BrowserRouter>` but outside `<AnimatedOutlet />`:** a single window `keydown` listener that maps ESC to a hierarchical parent route (`/chapters/:id` → `/chapters`, `/chapters` → `/`, `/plain` → `/`, `/` no-op) rather than `navigate(-1)`, so a deep-link or refresh can't ESC off-site. Direct user request ("pressing ESC from any place should take me to the previous menu"). Nothing else in this file changed. See `components/CLAUDE.md`'s `EscapeBack.jsx` row. **This batch — two new routes for the game surface (root `CLAUDE.md` §0.1 and phase 11):** `/floor` (`screens/Floor.jsx`, the walkable corridor behind NEW GAME) and `/play/:id` (`screens/Play.jsx`, the chrome around one minigame). Both are nested inside the **same** path-less `<Route element={<AnimatedOutlet />}>` layout as the other four, deliberately and not as a separate branch: that is what makes the camera dolly, the scroll reset and `<EscapeBack />` treat them like any other screen instead of needing special cases for a "game mode." The only files that had to learn the two new paths are the two lookup tables that were already the documented place for them — `PageTransition.jsx`'s `ROUTE_DEPTHS` (`/floor`=1, `/play/:id`=2, mirroring `/chapters` and `/chapters/:id`) and `EscapeBack.jsx`'s `parentOf()` (`/play/:id`→`/floor`, `/floor`→`/`). If you add a further game route, add it here and in those two tables, not by lifting it out of the layout. |
| `index.css` | ✅ | Imports Tailwind, `styles/tokens.css`, `styles/textures.css`; maps tokens into Tailwind's `@theme` so components can use `bg-ink`, `text-signal`, `font-display`, etc. instead of arbitrary values. Also carries the global focus-ring rule and the CSS-level `prefers-reduced-motion` fallback. **This batch:** `html { scrollbar-gutter: stable }` — `components/PageTransition.jsx`'s route dolly makes a screen `position: fixed` while it animates, which empties the document flow and takes the scrollbar with it, so without a permanently reserved gutter the page would jump sideways by the scrollbar's width at the start and end of every transition. It also removes the same jump between naturally short and long screens (title screen vs. `/plain`). **Also this batch, purely for that transition's performance:** a `.route-stage` utility (`will-change: transform, opacity` + `contain: paint`) that `PageTransition.jsx` attaches to the moving wrapper only while it is animating, promoting the ~1,450-rect SVG scene to a compositor layer so the zoom is a texture transform rather than a per-frame vector re-raster; and an `html.route-moving` block that pauses decorative CSS animation (`animation-play-state`, so they resume where they left off) for the duration of the move, since any repaint inside a promoted layer forces it to re-rasterize and would undo the promotion. Both are applied and removed by that one component — neither is a user preference, unlike the `motion-off` block above. **Phase 6:** now also carries a `.motion-off`-scoped mirror of that same reduced-motion block, toggled onto `<html>` by `components/AmbientLayer.jsx` whenever the Settings motion toggle is off — see that component and `styles/CLAUDE.md` for why a media query alone can't see in-app state. Otherwise treat as done; only touch if a new token is added to `tokens.css` and needs a matching `@theme` line. **This batch:** a `.no-scrollbar` utility (`scrollbar-width: none` + `-ms-overflow-style` + a `::-webkit-scrollbar { display: none }` rule), used by `screens/ChapterSelect.jsx`’s episode filmstrip. The raw OS scrollbar under that row read as a stray browser control bolted onto the art. It is safe to hide there specifically because that row has three other affordances — ◂ ▸ stepper buttons, Left/Right arrow-key support, and ordinary wheel/trackpad/touch scrolling — so this removes a bad affordance rather than the only one. Do not apply it to a container whose only scroll affordance is the bar itself. **This batch — a `@media print` block appended at the end**, for the `/plain` Dossier rebuild (`screens/PlainResume.jsx`, see that file's row and `screens/CLAUDE.md`). `/plain` is spec §2 rule 3's escape hatch and its "Download / print" button is `window.print()` — this block IS the PDF output a recruiter gets. Everything in it is scoped under `.dossier` (the root class on that screen's `<main>`) so it can never leak onto the three game screens, which carry no print styling of their own: forces true black-on-white (`background`/`color`/`border-color` overridden on every descendant) regardless of that screen's on-screen theme, hides everything classed `.dossier-chrome` (the section rail/mobile chip bar — one element, not two, see `screens/CLAUDE.md`'s signal-budget note — plus the control bar, the Download button, and the back link), forces the two-column `[16rem_1fr]` grid to a single column, forces every `<details>` body visible regardless of its `open` attribute as a CSS-only backstop alongside the JS-driven expand-before-print (belt and braces — a bare Ctrl+P's `beforeprint` event should commit React's state update before the browser paints, but there's no hard cross-browser guarantee of that ordering), and appends external link URLs after the link text (`a[href^="http"]::after`) since a printed page can't be clicked. One rule is deliberately **not** scoped to `.dossier`: `.texture-grain { display: none }` — the film-grain overlay is a `position: fixed` sibling of every screen mounted by `components/AmbientLayer.jsx`, not a descendant of any one screen's root, so a fixed full-viewport noise layer has no reason to appear on any printed page in this app and is suppressed globally rather than per-screen. **This batch — one rule appended at the very end for the game surface: `html:has(.game-surface) { background-color: var(--ink) }`.** The defect it fixes: `html { scrollbar-gutter: stable }` (added earlier in this same file, see above) permanently reserves a gutter strip, and that strip paints the **body** background — `--paper`. On the document screens that is invisible, but `/floor` and `/play/:id` are full-bleed dark, so a vertical band of cream ran down the right edge of both and read as a broken layout rather than as a scrollbar. Neither screen can fix it from the inside: the gutter is outside every element they render, so this has to be set on `<html>`. `:has()` was chosen over the obvious alternative — a `useEffect` in each screen toggling a class on the document element — precisely because a class needs a cleanup path for every way a screen can unmount, including `PageTransition.jsx` unmounting one mid-animation, and getting that wrong leaves the whole site stuck on an ink background. A selector has no cleanup path to get wrong. It is scoped to `.game-surface` (the root class on both game screens' `<main>`) so it can never reach the document screens, exactly like the `.dossier` scoping above. |

## Subfolders

- [`components/`](components/CLAUDE.md) — reusable UI primitives (Panel, DialogueChoice, toasts, etc.)
- [`context/`](context/CLAUDE.md) — React Context providers (progress, settings, and a new small one for the main-menu music's session-started flag)
- [`game/`](game/CLAUDE.md) — the playable layer: the canvas engine, the shared ink drawing vocabulary, the runtime palette bridge (canvas colours read from `styles/tokens.css` so no scene ever holds a hex literal), the React host, and the six scenes — the `/floor` overworld plus one minigame per episode. Read that file before touching anything under it; the engine interface is frozen against five scenes.
- [`data/`](data/CLAUDE.md) — single source of truth for all resume content (`episodes.js` = the curated game surface, organized by category — education, academia, leadership/volunteering, hackathons, projects — not chronology; `profile.js` = everything else the `/plain` document needs)
- [`lib/`](lib/CLAUDE.md) — non-visual utilities: `sound.js` (synthesized UI sound engine) and `musicPlaylist.js` (new — auto-discovers the main-menu lofi tracks in `assets/audio/`)
- [`screens/`](screens/CLAUDE.md) — route-level screens (all 4 built, routing wired)
- [`styles/`](styles/CLAUDE.md) — design tokens and texture CSS
- [`assets/`](assets/CLAUDE.md) — fonts, cover images, title art (all empty)

## Rule reminder

`data/` is the only place content may live — `data/episodes.js` for the
five-episode game surface, `data/profile.js` for the contact/education/
skills/awards material that only the `/plain` document renders, and (new
this batch) `data/games.js` for the minigame layer's short beats. That
third file is a shorter cut of the SAME facts, never new ones — see
`data/CLAUDE.md` for the rule every beat has to satisfy. No file
directly under `src/` (i.e. `App.jsx`) may hardcode resume copy — it
composes screens/components that read from `data/`. Nothing under
`game/` may hardcode copy either: a scene owns a mechanic, `games.js`
owns every word a player reads.
